# 小红书薯条内容加热审核 Skill

## 概述

本技能用于审核小红书笔记内容是否符合薯条内容加热规范，帮助用户在投放前发现并修复潜在的审核风险。

## 使用流程

### 第 1 步：获取待审核内容

用户可能通过以下方式提供内容：
- 直接粘贴笔记文案（标题 + 正文）
- 上传图片（需要 OCR 识别文字内容）
- 描述笔记的主题和大致内容
- 提供笔记链接（提示用户粘贴文案，因为无法直接访问小红书笔记）

如果用户只提供了部分信息，主动询问：
- 笔记的完整标题和正文
- 涉及的产品/品牌/行业
- 是否包含图片/视频中的文字信息
- 笔记类型（纯分享 vs 商业推广/合作笔记）

### 第 2 步：加载审核规则

阅读完整审核规则：
```
查看 references/review-rules.md
```

### 第 3 步：逐项审核

按以下 **7 个维度** 逐一检查，每个维度给出结论：

#### 维度 1：法律法规合规性
检查内容是否触及法律红线（国家领导人、国旗国歌、色情暴力、歧视、迷信等）。

#### 维度 2：行业准入
对照禁止加热行业名单，判断笔记涉及的行业/产品是否在黑名单中。重点关注：
- 医疗健康类（处方药、整形、减肥产品等）
- 金融类（几乎全部禁止）
- 招商加盟类（全部禁止）
- 教育培训类（校外学科培训禁止）

#### 维度 3：社区规范
检查是否存在不文明行为、作弊行为、损害平台利益的内容。

#### 维度 4：内容质量与导向
检查是否存在：虚假信息、低质量素材、不良价值观导向、非原创内容等。

#### 维度 5：平台元素合规
检查是否假借小红书名义、未经授权使用平台元素、使用录屏截屏等。

#### 维度 6：营销推广合规（重点检查）
这是最常见的违规点，仔细检查：
- **绝对化用语**：最佳、最好、第一、唯一、100% 等
- **虚假夸大**：超出产品本身功效的宣传
- **虚假效果图/承诺**："X天白X度""X天瘦X斤" 等
- **伪科普软广**：假借科普/养生/个人经历推广产品
- **恶意对比**：贬低竞品、拉踩行为
- **导流行为**：微信号、手机号、二维码、外部链接、水印
- **过度营销**：违规商业招揽

#### 维度 7：话题聚类风险（新增）

单词级别的替换不能解决话题级别的限流。XHS 算法会对整篇笔记的话题分布做聚类识别，即使把「两党」「抗议」等词都替换掉，整篇新闻仍因话题聚类触发限流。

**🔴 HIGH（命中即建议整条剔除或 swap）：**
- 美国国内政治：两党、共和党、民主党、Sanders、Trump（作为政治人物）
- 示威 / 抗议 / 游行 / 骚乱 / 罢工
- 枪击 / 袭击 / 燃烧瓶 / 暗杀等人身安全事件
- 政府机构政治语境：国防部 / 财政部 / 五角大楼 / 司法部 / FBI / CIA
- 主权红线：台独 / 港独 / 疆独 / 藏独 / 涉疆 — **一票否决，硬剔除**

**🟡 MEDIUM（可保留但必须剥离政治角度或降级）：**
- AI 监管（EU AI Act / 出口管制 / AI 行政令）— 改写为「出台 AI 法案」而非政治化叙事
- 地缘政治中的 AI 芯片话题 — 聚焦技术细节、回避制裁叙事
- 医疗 AI（cancer/NHS/pharma/医疗/诊疗/处方/疗效）— XHS 医疗行业黑名单，限 T3 briefs
- 消费金融 AI（银行/炒股/股价/理财/基金）— XHS 金融行业黑名单，限 T3 briefs
- 宗教 / 信仰主题（基督教/牧师/伊斯兰/佛教）— T2/T3 可用，禁止 T1

**🟢 LOW（词级别替换即可）：**
- 纯产业商业：并购 / 融资 / 产品发布 / 人事
- 技术 / 研究 / 开源 / 基准测试
- **中国正面 AI 生态**（DeepSeek / Qwen / Kimi / 通义 / 昇腾 等 × 发布/开源/论文）— 鼓励进 T1/T2

**审核动作映射**：
- HIGH → swap 整条或删除（在 digest.json 与 xiaohongshu-post.md 同步处理）
- MEDIUM → 改写成 AI-native 角度（例：「Trump 官员劝银行测 Mythos」→「多家银行开始评估 Anthropic 的 Mythos 安全模型」）
- LOW → 按维度 1-6 的词级别规则替换即可

**与 score-engine 的联动**：score-engine 的 `classifyTopic()` 已在评分阶段给出 `topic_hint` + `topic_adjustment`。xhs-reviewer 在审核阶段**重新确认**话题判定，特别关注 score-engine 遗漏的中文语境（模型正则未必覆盖所有变体）。

## 审核原则

1. **宁严勿松**：拿不准的内容标记为 ⚠️ 需修改，而非直接放过
2. **具体定位**：指出问题时，引用笔记中的具体文字或描述
3. **给出替代方案**：对于可修改的问题，提供具体的替换文案建议
4. **区分硬伤与软伤**：
   - 硬伤（❌）：行业黑名单、法律红线 → 不可修改，建议放弃加热
   - 软伤（⚠️）：用语不当、轻微夸大 → 可修改后重新提交
5. **关注隐性风险**：特别注意伪科普软广、隐性导流等不容易发现的违规

## 敏感词替换策略（CRITICAL）

**完整替换对照表（唯一权威来源）** → `skills/news-card/references/config/sensitive-word-dict.md`

替换优先级：中文同义改写 > 英文正确大写 > Unicode 数学字体。

> **注意**：「数据」「攻击」「漏洞」已确认**无需替换**（2026-04-14 用户修订）。

### 反面案例（禁止）

- ❌ `cybersecurity模型` — 生硬英文插入，破坏阅读节奏
- ❌ `data center` — 小写英文看起来像占位符
- ✅ `网络防御模型` — 自然、通顺、不触发限流
- ✅ `Data Center` — 正确大写，作为专有名词可接受
- ✅ `公共利益` — 完全用中文绕开「安全」

## 常见易错点提醒

- "全网最低价" → 绝对化用语，违规
- "亲测有效，X天见效" → 可能涉及虚假夸大
- "加 V 了解更多" → 导流行为，违规
- "小红书推荐好物" → 假借平台名义，违规
- 普通食品宣传"降血压""助睡眠" → 超出功效宣传，违规
- 普通化妆品宣传"祛斑美白" → 特殊化妆品功效，违规
- 笔记中出现其他平台 logo/水印 → 损害平台利益，违规
